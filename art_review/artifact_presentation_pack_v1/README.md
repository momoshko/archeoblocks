# Archeoblocks — Ancient Courtyard Artifact Presentation Pack v1

M2.5B. Изображения для рассмотрения перед интеграцией. Сцены, ресурсы экспедиций,
gameplay markers и правила игры не изменены. Папка исключена из импорта Godot
файлом `.gdignore`; при будущей интеграции переносить только выбранные PNG.

ортографический вид рельефа, освещение сверху слева. Ни текста, ни UI-рамок,

## Отношение фрагментов к маске

Три production-фрагмента извлечены из одного подготовленного изображения маски
по двум дополняющим друг друга неровным границам. Маска не перерисовывалась для
каждого фрагмента. Каждая часть содержит примерно треть видимой площади находки.
Есть небольшие нерегулярные сколы силуэта; нет пазов, похожих на детский пазл.

В отдельных PNG фрагменты центрированы **только целочисленным переносом**.
Масштаб всех частей совпадает с масштабом полной маски. Для сборки применить
`assembly_translation_px` из manifest к положению соответствующего PNG:

`fragment_position = full_mask_position + assembly_translation_px * display_scale`

При переносе в atlas сохранять либо 512×512 canvas, либо учитывать обрезку
`centered_sprite_rect_px`. Нельзя независимо растягивать три части при сборке.
`golden_mask_fragments_assembly.png` показывает разнесённые части, их реальную
сборку и исходный восстановленный master рядом. `validation.json` содержит
сравнение RGBA видимых пикселей собранных **экспортированных** PNG с master.

## Fit и padding

- Полные артефакты вписаны по длинной стороне в 384 px внутри 512 px canvas:
  минимальный внешний запас — 64 px. Фрагменты сохраняют общий масштаб,
  поэтому их вертикальные прозрачные поля больше.
- Для отдельной иконки в прогрессе или reveal брать alpha bounds из manifest
  и вписывать их пропорционально. Это не тот же режим, что сборка целой маски.
- В обзоре 48 px показаны два режима: весь production canvas, затем alpha bounds
  вписанные в 40 px. Вторая строка лучше передаёт отдельные фрагменты.
- Для in-cell review видимый объект вписан в 70% стороны клетки. Основа взята
  из настоящего `Core Cell Pack v2 / cell_excavated_depth0_v2.png`.
  Это пример fit, а не изменение игрового рендера.
- Сохранять пропорции, использовать линейную фильтрацию при уменьшении.
  Не добавлять золотую маску целиком в каждую клетку.

## Генерация и техническая подготовка

Рисунки созданы встроенным **imagegen**; исходные запросы и назначение референсов
сохранены в `prompts.json`. `sources/` хранит выбранные исходные рисунки и
отдельно сгенерированные пробные фрагменты. Это не production PNG.

У печати исходник уже имел alpha. Генератор маски и амулета нарисовал шахматную
подложку в RGB, несмотря на запрос прозрачного PNG. При экспорте удалён связный
ахроматический фон; у амулета также очищено отверстие петли. Цветной рисунок
сохранён, края уменьшены на один пиксель исходного разрешения для удаления каймы.

Отдельные генерации фрагментов сохранили стиль, но изменили геометрию и повторили
часть носа. Поэтому они оставлены **только как style references**, а финальные
части получены точным разбиением общего master. Они не являются тремя независимо
сгенерированными предметами. `build_pack.cjs` воспроизводит технический экспорт,
листы обзора и проверки; он не обращается к Godot и не генерирует новый рисунок.

## Оставшиеся риски читаемости

- На 48 px уверенно различаются круглая печать, вытянутый амулет и лицо маски.
  Мелкие гравировки перестают читаться и служат только фактурой.
- Средний фрагмент широкий: при размере всей иконки 48 px его высота невелика.
  Для progress UI полезно вписывание по alpha bounds; для cell reveal потребуется
  ручная оценка на устройстве.
- Неровные границы фрагментов дают точную сборку, но не имеют отдельно
  нарисованной объёмной толщины излома. Это компромисс v1 между стыковкой и
  детализацией отдельных обломков.
- Маска заметно более полированная, чем каменные находки: это поддерживает
  ценность финальной награды, но баланс яркости нужно оценить в будущих popup.
- Чистота краёв просмотрена на тёмной и светлой подложке. Финальные настройки
  сжатия и импорта, реальный popup и поведение на мобильном экране пока не проверялись.

Godot-тесты не запускались: задача ограничена подготовкой изображений.
