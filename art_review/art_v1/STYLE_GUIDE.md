# Archeoblocks · ART V1

**Foundation milestone · 15 сентября 2026 · выбранное направление: «Светлый песчаниковый двор».**

Это стандарт для следующего visual pass и два screen references. PNG экранов нельзя переносить в игру как цельную подложку интерфейса. Все подписи, кнопки, счётчики и состояния остаются отдельными узлами сцен. ART V1 не меняет правила, экономику и layout в Godot.

## 1. Направление и baseline

Тёплая, сделанная руками археологическая головоломка: крупные простые формы, мягкий каменный объём, спокойный светлый интерфейс и насыщенные минералы в игровом поле. Ощущение ценности создаётся материалом и ясной композицией. Старина выражена редкими сколами и вытертыми гранями, а не шумом на каждой поверхности.

| Вариант внутри общей стилистики | Сильная сторона | Ограничение | Решение |
| --- | --- | --- | --- |
| Светлый песчаниковый двор | Светлая оболочка отделяет тёмное поле; естественно продолжает текущие материалы | Нужна сдержанность тёплых оттенков | **Основной ART V1** |
| Полевой дневник | Пергамент удобен для коллекции и длинных текстов | Бумажность ослабляет каменную тактильность головоломки | Только мягкость текстовых панелей |
| Тихие катакомбы | Хорошо поддерживает корни и Chapter III | Тёмные панели сливаются с полем, тяжелее меню | Только периферийные зелёные акценты |

Решение принято для этого milestone; это выбор арт-направления, а не утверждение пользователем каждого будущего ассета.

| Светлая грань | `#F1E5CD` | Узкая верхняя грань, без белого свечения |

| Корни | `#414A32`, `#615038` | Тёмная олива и органический коричневый |

Золото занимает маленькие локальные участки. У панелей, обычных кнопок, selection и hint нет золотой заливки. Amber отличается от золота оранжевой серединой и квадратным выпуклым силуэтом. Цвет блока косметический: нельзя делать от него зависимым смысл хода.

## 3. Материал, свет и форма

- Единственный основной свет сверху слева. Верхняя левая грань светлее, нижняя правая темнее. Ни отдельной подсветки каждого артефакта, ни HDR.
- Песчаник: широкая матовая плоскость, редкая неоднородность, 1–2 скола на модуль. Скалывание не нарушает hitbox и безопасную область текста.
- Пергамент: мягкое тональное пятно, без рваного свитка, завитков и текстуры под буквами.
- Минерал: плоская читаемая середина, мягкая фаска, максимум одна слабая прожилка. Он выступает над грунтом.
- Excavated: вдавленная форма. Затемнение верхнего внутреннего ребра и свет на нижнем внутреннем ребре помогают отличать яму от блока даже без цвета.
- Камни: компактный неправильный многогранник; усиленный вариант шире внутри того же canvas, с двумя крупными структурными гранями. Никаких металлических ремней, означающих новую механику.
- Корни: 2–3 широких переплетающихся отростка, просвет между ними, преимущественно диагональное направление. Нельзя превращать корни в зелёный квадрат.
- Панели: мягкий прямоугольник; кнопки — более аккуратный прямоугольник; артефакты — самостоятельные круглый, вытянутый или лицевой силуэты. Общая форма важнее гравировки.

## 4. UI hierarchy и масштабы

**Порядок внимания в игре:** поле → активная фигура/подсказка → цель и фрагменты → доступные действия → счёт и атмосфера.

Рабочая система координат — **720×1280**, как в `project.godot`. Это логические единицы, а не требование физического разрешения PNG. Референсы масштабируются целиком без растяжения пропорций.

| Область | Production intent |
| --- | --- |
| Меню | Панель в полях около 56; эмблема выше названия; «Играть» заметно сильнее трёх вторичных кнопок |
| Заголовок игры | Пауза слева; длинное название переносится на две строки; фрагменты рядом с названием |
| Цель | Основная строка 26–28; пояснение 22–24 и допускает перенос |
| Поле | Ортографическое 8×8, без перспективы. В baseline pitch около 63 логических px; ART V1 сохраняет сопоставимый размер |
| Слоты | Три равных места, одинаковый масштаб элементарного блока; длинная Г действительно содержит пять клеток |
| Действия | Две спокойные кнопки ниже слотов; состояния available/disabled/pressed обязательны позднее |
| Статистика | Ходы слева, счёт справа, ниже действий |

Типографика: кириллический читаемый sans для UI, medium/semibold. Для названия допустим характер резной надписи, но сохраняется текстовый узел; production-шрифт проверяется отдельно. На 720: название меню 54–60, primary CTA 30–32, кнопки 26–28, вторичные подписи не меньше 22. На 360 px ширины это примерно половина указанных размеров; длинные подписи требуют реальной мобильной проверки. Не обещать полноценную читаемость мелких гравировок.

Для будущей адаптации на 360/390/430 CSS px сначала сохранять квадратное поле и безопасные поля, затем давать тексту переноситься. Не ужимать игру по вертикали до нечитаемого размера. Touch target паузы и действий — минимум 44 CSS px после масштабирования; для нынешних 64–68 логических px это потребует увеличения hit area в следующем UI milestone, без изменения силуэта картинки.

## 5. Состояния клетки и правила чтения

| Состояние | Обязательный визуальный сигнал | Что исключить |
| --- | --- | --- |
| Soil depth 2 | Тёмная плотная охра; широкие редкие трещины; плоская поверхность | Каменная холодная фаска и золотой ободок |
| Soil depth 1 | Светлее depth 2; мягкая рыхлая поверхность | Выступающий блочный профиль |
| Excavated cell | Тёмная вдавленная полость, очень тихая кромка | 64 одинаково яркие рамки |
| Occupied block | Непрозрачный цветной минерал, выпуклая фаска | Прозрачность, похожая на hint |
| Artifact marker | Маленький золотой ромб в тёмном кольце + тонкий контур клетки; читается поверх блока/препятствия | Подмена marker конкретной маской; исчезновение под блоком |
| Stone | Холодный матовый обломок, одна прочность | Зелёный/золотой цвет; сходство с землёй |
| Reinforced stone | Более цельный массив и **два коротких светлых штриха прочности**, один после повреждения | Надежда только на мелкие трещины или оттенок |
| Root | Широкий узел с просветом, без геометрической фаски | Моховая плитка, закрывающая клетку полностью |
| Hint ghost | Та же форма и цвет выбранной фигуры, alpha 0.30–0.40, тонкий светлый пунктирный контур; грунт виден | Непрозрачный блок, галочки, золото selection |
| Valid placement | Непрерывный бирюзовый контур + галочка, прозрачная середина | Отличие только зелёным оттенком |
| Invalid placement | Терракотовый контур + X, прозрачная середина | Закраска препятствия, прячущая причину отказа |
| Root growth warning | Отдельный оливковый контур и направленный отросток/указатель к целевой клетке | Золотой ромб цели или hint-квадрат |

Hint и drag preview взаимоисключающие, как в текущем renderer. На master показывается **hint**, а не одновременный valid/invalid drag. Два состояния drag описаны здесь для отдельной будущей проверки.

### Контракт слоёв

Terrain base → подходящий burial/artifact visual → occupied block **или** obstacle → hint/placement feedback → artifact target marker → transient feedback. Root warning — отдельный слой с собственным сигналом. Преграда и размещённый блок не могут одновременно занимать одну клетку.

Marker — семантическая цель, а artwork — внешний вид находки. Даже если грунт/предмет скрыт камнем или блоком, marker остаётся различимым. Подсказка не означает уже сделанный ход и не открывает фрагмент. Не показывать собранную награду в клетке, если игровое состояние ещё её не открыло.

Сохранять общий canvas клеточных слоёв **256×256** и content rect **[8,8,240,240]** из v2. Блоки: bounds 220×220, padding 18 px из v1. Артефакты: 512×512, вписывание по собственному silhouette contract; не увеличивать фрагменты независимо при сборке маски. Ни один размер из master PNG не заменяет manifest исходного набора.

## 6. Допустимо / запрещено

**Допустимо:** редкая фактура, асимметричный скол, мягкая локальная тень, один спокойный орнамент на большой панели, ограниченная зелень по краям экрана, отдельные состояния для feedback.

**Нельзя:** текст в production PNG кнопок; золотые рамки всего UI; lens flare; частицы в спокойном состоянии; фальшивые счётчики; перспектива поля; 7×8 или 9×8 сетка; произвольные фигуры; новые игровые ресурсы; decoration поверх playable area; debug/reward cheats в release; глобальная отрисовка интерфейса скриптом вместо сцен.

## 7. Критерии следующего asset pass

1. Проверить cell/obstacle/marker на 48 px, затем на фактических ~31–35 CSS px мобильного поля.
2. В grayscale отличать выпуклый блок, углубление, камень, корень и marker по форме, а не только тону.
3. Проверить marker поверх всех шести блоков, двух прочностей камня и корня; hint — на всех трёх terrain states.
4. Для обычного текста целиться в контраст ≥4.5:1, для крупного — ≥3:1. Проверять плоские токены и реальные фоны; художественный PNG сам по себе этого не гарантирует.
5. Проверить repeat 8×8 без случайных вращений, которые меняют направление света.
6. Проверить длинные русские строки, disabled actions, низкий экран, Web scaling и touch targets после интеграции. В ART V1 этих runtime-проверок нового арта ещё нет.
